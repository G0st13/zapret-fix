# ZapretFix — обход DPI для YouTube / Discord / Telegram без VPN

Настроено и **проверено на твоей машине** (`DESKTOP-5U5K3RP`, Windows 11 Pro build 26200).

## Текущее состояние — работает

```
YouTube : HTTP 204, TCP 64ms, TLS 100ms, 139 КБ/с
Discord : HTTP 200, TCP 38ms, TLS 76ms
Telegram: 0/4 DC — блок по IP, нужен MTProto-прокси
Служба  : zapret — RUNNING, автозапуск, 1 процесс winws
Стратегия: simple (весь TCP 80/443, fake+fakedsplit)
```

Служба `zapret` поднята через `nssm` и стартует вместе с Windows. Проверь сам:
открой YouTube и Discord — должны работать без VPN.

**Управление:**
```powershell
.\RUN.bat                                         # перепроверить/переустановить (UAC)
powershell -File .\Fix-Zapret.ps1 -Mode Status    # проверить состояние
powershell -File .\Fix-Zapret.ps1 -Mode Stop      # выключить обход
powershell -File .\Fix-Zapret.ps1 -Mode Start     # включить обратно
powershell -File .\Fix-Zapret.ps1 -Mode Telegram  # подобрать прокси для Telegram
powershell -File .\Fix-Zapret.ps1 -Mode Restore   # полный откат (hosts, DNS, служба)
```

Скрипт защищён от параллельного запуска (именованный мьютекс): два экземпляра
дерутся за `winws`, и замеры превращаются в мусор. Второй запуск просто выйдет с
предупреждением. Автоподбор стратегии также сам гасит уже работающую службу —
иначе её `winws` держит драйвер и новый экземпляр не стартует (код 1).

## 1. Что нашлось при сканировании

| Параметр | Значение |
|---|---|
| Основной адаптер | Wi-Fi `MediaTek Wi-Fi 6 MT7920` — `192.168.0.102/24`, шлюз `192.168.0.1` |
| Лишние адаптеры | `Radmin VPN` (`26.82.20.213`, метрика 9257), `vEthernet (WSL)`, Teredo |
| Блокировки | **YouTube** — подмена DNS + SNI/TLS; **Discord** — TCP проходит, TLS режется; **Telegram** — блок по IP (все DC молчат на 443/80/5222/993/8080) |

**Что было сломано в системе:**

1. **Служба `zapret` ссылалась на удалённую папку** `Desktop\zapret-discord-youtube-1.9.1\bin\winws.exe` — автозапуск был, но запустить её Windows не мог.
2. **`hosts` заражён**: 93 записи-заглушки. ChatGPT, Claude, Anthropic, Sora, Spotify, Notion, DeepL и десятки поддоменов шли на мёртвый `74.119.194.9`, плюс 40 фейковых «FitGirl» на `109.94.209.70`. Это следы установщика пиратского софта — они блокировали AI-сервисы **независимо от провайдера**. Вычищено, бэкап в `C:\ProgramData\ZapretFix\backup\`.
3. **`ipset-all.txt` был обнулён** до 18 байт (заглушка `203.0.113.113/32`). Восстановлен из `ipset-all.txt.backup` — **12 063 подсети**.
4. **DNS подменялся провайдером**: `youtube.com` → NXDOMAIN даже через 8.8.8.8. Включён DoH (Cloudflare через `netsh dns add encryption`), только на основной адаптер.

## 2. Что реально заставило это работать

Три вещи, которые я нашёл только на живой системе — без них скрипт ставил «рабочую» стратегию и всё равно ничего не работало:

### 2.1 `HttpWebRequest` врал при замерах (главное)

Первая версия мерила доступность через `[Net.HttpWebRequest]`. Он держит пул соединений (ServicePoint): как только запрос к хосту один раз упал по таймауту, **все последующие запросы к тому же хосту падают мгновенно** — даже когда канал уже работает.

Симптом: каждая стратегия «проваливалась» за 5 секунд вместо 30 (таймаут 10 с + 10 с + 12 с). Настоящая рабочая стратегия получала `score = 0`.

Заменено на **сырые сокеты** (`TcpClient` + `SslStream`, своё соединение на каждый запрос) с постадийной диагностикой: `DNS → TCP → TLS → HTTP`. Теперь видно, на каком именно этапе рвётся.

### 2.2 Ведущий `--new` ломал весь обход

В zapret `--new` разделяет фильтры. Если поставить `--new` перед **первым** фильтром, создаётся пустой фильтр, который перехватывает трафик и ничего с ним не делает — обход перестаёт работать целиком.

Мои конфиги генерировались как `--wf-tcp=... --new --filter-tcp=80,443 ...`. Штатные `.bat` из комплекта zapret так не делают: первый фильтр идёт без `--new`. Исправлено — и это была та самая разница между «падает» и «работает».

### 2.3 Списки `--hostlist` на этой сети не сопоставляются

Изоляция на живой системе показала: **все** конфиги с `--hostlist` дают ровно тот же результат, что и полное отсутствие обхода. Правило «десинкать весь TCP 80/443» работает.

```
A. ПОЛНЫЙ со списками        -> TLS таймаут (как без обхода)
B. БЕЗ списков + ip-id=zero  -> YouTube HTTP 204, Discord HTTP 200   <- рабочий
```

Поэтому основная стратегия теперь **без списков**: десинхронизируется весь TCP 80/443, а локальные сети защищены `--ipset-exclude`. Списки всё равно восстановлены и нормализованы к LF (`zapret` родом из Linux, CRLF-строки могут не матчиться) — они используются в запасных стратегиях.

Рабочая стратегия — `simple` (fake+fakedsplit, fooling=ts). Вариант `simple+ipid0` с `--ip-id=zero` тоже рабочий; в итоге установился `simple`, потому что при автоподборе `simple+ipid0` не смог занять драйвер, пока его держал старый экземпляр службы.

## 3. Побочные баги, найденные и исправленные по ходу

| Баг | Как проявлялся |
|---|---|
| Запятая в PowerShell связывает крепче `+` | `@($env:ProgramData + '\a', '\b')` склеивал весь список путей в одну строку — автопоиск zapret не находил ничего |
| `Find-ZapretToolchain` выбирал собственную папку | На повторном запуске источником становился `C:\ProgramData\ZapretFix\bin` (score 31 > 20), и `Install-Lists` копировал списки **сам в себя** — `.backup` не находился. Теперь своя папка получает −100 и идёт последней |
| Фильтр `*.txt` не захватывал `.backup` | `ipset-all.txt.backup` (210 КБ) не копировался, восстановление ipset не срабатывало |
| Кириллица в `hosts` | Файл ASCII — комментарии превращались в `????`. Переведены на латиницу |
| DNS ставился на все адаптеры | Включая `Radmin VPN` и `vEthernet (WSL)`. Теперь — только на интерфейс маршрута по умолчанию |
| Залипание драйвера WinDivert | `Stop-Process -Force` не закрывает хендл, драйвер режет трафик (`WSAEACCES`). Добавлены ожидание здоровья сети, контрольная проверка `1.1.1.1` и снятие драйвера только при необходимости |
| DoH включался вслепую | Если DoH не поднимется, машина осталась бы без разрешения имён. Добавлена предварительная проверка и аварийный откат DNS |

## 4. Telegram — решено через TG WS Proxy

**Десинхронизация DPI тут не поможет.** Проверено: все дата-центры Telegram (`149.154.167.99/51`, `149.154.175.50`, `91.108.56.130`) не отвечают на 443, 80, 5222, 993 и 8080. Это блокировка по IP-адресам — SYN-пакеты уничтожаются до всякого DPI. Ни zapret, ни GoodbyeDPI такое не обходят принципиально.

Рабочее решение — **`tg-ws-proxy`** из папки `Desktop\tg-ws-proxy-main`: локальный MTProto-прокси, который уходит в Telegram не по заблокированному TCP, а через WebSocket/HTTP-2 поверх Cloudflare. Это не VPN — проксируется только трафик Telegram.

### Что сделано

- Python 3.14.3 найден; в папке исходники v1.11.2, готового exe нет.
- Доустановлены отсутствовавшие зависимости: `customtkinter`, `pystray`, `pyperclip`, `psutil`, `h2` (`httpx[http2]`).
- Приложение запущено, конфиг создан: `%APPDATA%\TgWsProxy\config.json`.

### Параметры подключения

```
Тип    : MTProto
Сервер : 127.0.0.1
Порт   : 1443
Secret : <GENERATED_AT_STARTUP>
Ссылка : tg://proxy?server=127.0.0.1&port=1443&secret=<GENERATED_AT_STARTUP>
```

Приложение при старте само открывает `tg://proxy` — Telegram подхватывает настройки автоматически.

### Запуск

Ярлык на рабочем столе: **`Запустить TG прокси.bat`** — двойной клик, появляется иконка в трее.

Проверено в работе: `WS pool hit`, `DC2 media`, суммарно `down=59.5MB` через прокси — трафик Telegram реально идёт.

**Важно:** пока прокси не запущен, Telegram будет висеть в «подключении», потому что в его настройках уже прописан `127.0.0.1:1443`. Либо запусти ярлык, либо отключи прокси в Telegram (Настройки → Продвинутые → Тип подключения).

Меню трея: «Открыть в Telegram», «Скопировать ссылку», «Перезапустить прокси», «Настройки…», «Открыть логи», «Выход». Автозапуск включается в настройках приложения.

Альтернатива без локального приложения — публичные MTProto-прокси: `Fix-Zapret.ps1 -Mode Telegram`.

## 5. Ограничения

- Стратегия `simple+ipid0` десинхронизирует **весь** TCP 80/443, а не только нужные домены (потому что списки на этой сети не работают). Обычно это безопасно, но если какой-то сайт начнёт чудить — `-Mode Stop` выключает обход, `-Mode Start` включает.
- Скрипт не проверялся на другой сети/провайдере: он настроен под конкретно твою. При смене провайдера запусти `-Mode Strategy`.
- `-Mode Restore` возвращает `hosts`, DNS и удаляет службу. Файлы в `C:\ProgramData\ZapretFix` остаются (там бэкапы и логи) — удаляются вручную.
- Логи: `C:\ProgramData\ZapretFix\logs\`, отчёт диагностики: `diagnose-report.txt`.
